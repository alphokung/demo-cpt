Envelope Encryption Demo

คำนวณจริงด้วย Web Crypto API ในเบราว์เซอร์ของคุณ — HKDF-SHA256 และ AES-256-GCM ตัวเดียวกับ production ไม่มีข้อมูลถูกส่งออกไปไหน ทำตามลำดับ STEP 1 → 5

เบราว์เซอร์นี้ไม่รองรับ Web Crypto (crypto.subtle) — ลองเปิดผ่าน Chrome/Edge/Firefox เวอร์ชันปัจจุบัน
STEP 1

Rotation — สร้าง Master Secret (KDK)

จำลอง GenerateDataKey: สุ่ม 32 bytes จาก CSPRNG — ใน production ตัว plaintext นี้อยู่ใน memory ชั่วครู่แล้วถูก wrap เก็บ DB · กด Rotate ซ้ำเพื่อดู version เลื่อนสถานะ

ยังไม่มี master secret — กดปุ่มด้านบน

หมายเหตุ: MS ไม่มี "ข้อความต้นฉบับ" — เป็นเลขสุ่มบริสุทธิ์ 32 bytes จาก CSPRNG ทุก bit คือ entropy ไม่ได้แปลงมาจากข้อความ/รหัสผ่าน/สูตรใดๆ (นี่คือคุณสมบัติที่ต้องการ)

STEP 2

Derive DEK ด้วย HKDF-SHA256

DEK = HKDF(MS[active], salt=dataset, info=SHA-256(citizen_id)) — ลองเปลี่ยนเลขแค่หลักเดียวแล้ว derive ใหม่ DEK จะเปลี่ยนทั้งเส้น

รอ master secret ก่อน

หมายเหตุ: DEK ไม่มี "ข้อความต้นฉบับ" — เป็นผลคำนวณ HKDF จาก input ที่อ่านได้ (แสดงในบรรทัดสถิติหลังกด Derive) ตัวผลลัพธ์ต้องดูไม่ต่างจากเลขสุ่ม และคำนวณย้อนกลับหา input ไม่ได้

STEP 3

Encrypt — AES-256-GCM + AAD → Blob

nonce สุ่มใหม่ 12 bytes ทุกครั้ง · AAD = citizen_id ‖ dataset ‖ version ‖ created_at ผูกบริบทกันสลับ blob

STEP 4

Verify — AAD ถูก "ประกอบใหม่" ไม่ได้อ่านจาก blob

AAD เป็น plaintext เสมอโดยนิยาม (Additional Authenticated Data — ไม่ใช่ Encrypted) จึงไม่มีขั้น "ถอดรหัส AAD" อยู่จริง และ design นี้จงใจไม่เก็บมันลง blob — ฝั่งถอดต้องประกอบขึ้นใหม่จาก 2 แหล่ง: citizen_id ที่ผู้เรียกส่งมากับ request + ค่าที่อ่านได้จาก header ส่วน gcm_tag คือ "ตราครั่ง" (MAC ทางเดียว) ที่ใช้เทียบได้อย่างเดียว ดึง AAD หรือข้อมูลใดๆ กลับออกมาจากมันไม่ได้ — ขั้น ③ จะโชว์ tag ที่คำนวณใหม่เทียบกับ tag ที่เก็บไว้ให้เห็นกับตา

STEP 5

Decrypt · Tamper · ข้าม version

decrypt จะ derive DEK เดิมขึ้นมาใหม่จาก version ใน header — ลองแก้ 1 bit หรือเปลี่ยน citizen_id ดูว่า GCM จับได้ไหม · ลอง Rotate ใน STEP 1 ก่อนแล้วค่อยกด Decrypt เพื่อดูว่า blob เก่ายังถอดได้

เปิดไฟล์นี้ตรงๆ ได้เลย — ต่อเน็ตครั้งแรกเพื่อโหลดฟอนต์เท่านั้น ตัว crypto ทำงาน offline ทั้งหมด
